# Catatan Skema D1 - Ciccu Store

Format: Markdown. Blok kode memakai triple backtick.
File ini adalah peta referensi struktur database `ciccu` (Cloudflare D1 / SQLite).
Sumber kebenaran: output `sqlite_master` produksi. Perbarui file ini setiap kali
schema berubah. Jangan pakai file ini untuk menebak nama kolom - selalu cocokkan
dengan schema live sebelum menulis query baru.

Cara pakai cepat:
- Buka file ini sebelum menulis query baru, sebelum migration, atau sebelum refactor.
- Bagian paling sering menyelamatkan dari bug diam-diam: "Uang", "Tabel hantu",
  "Checklist", dan catatan idempotency di `rsl_orders`.

---

## 1. Peta domain

| Domain | Tabel | Dipakai oleh |
|---|---|---|
| Publik (etalase) | pricelist, app_forms, testimonials, app_metadata, store_settings | /pricelist/ + /api/* |
| Reseller | rsl_* | /reseller/ + /api/reseller/* |
| Auth admin | admin_sessions | /admin/ + /api/admin/* |
| Config toko | store_settings (singleton) | admin + publik + reseller (flash) |
| Internal CF | _cf_KV | jangan disentuh manual |

---

## 2. Aturan baca cepat

- Semua waktu disimpan UTC (`datetime('now')`). WIB hanya dikonversi di frontend
  (`parseWIB` = kurangi 7 jam). Perbandingan string waktu di backend mengandalkan
  format `YYYY-MM-DD HH:MM:SS` yang konsisten dari `nowStr()`.
- Uang punya DUA format (TEXT manusia vs INTEGER rupiah penuh). Jangan tertukar.
  Lihat bagian "Uang".
- Kolom `fields` di `rsl_stock_items` dan `rsl_order_revisions` berisi CIPHERTEXT
  (encrypted JSON), bukan plaintext. Jangan pernah menulis plaintext ke kolom ini.
- Ada beberapa tabel legacy kembar (hantu). Jangan salah pakai. Lihat "Tabel hantu".
- Hanya `rsl_order_revisions` yang punya FK constraint. Relasi tabel lain manual,
  dijaga kode. Lihat "Relasi logis".

## 3. Tabel publik

### pricelist
Etalase publik. Kolom: `id`, `app_name`, `category`, `duration`, `price` (TEXT),
`notes`, `status` (DEFAULT 'Ready', kapital R), `app_sort_order` (DEFAULT 9999),
`sort_order` (DEFAULT 9999), `flash_price` (TEXT DEFAULT ''), `flash_sort_order` (DEFAULT 9999).
- `price` / `flash_price` format manusia ("50K", "100.000"), bukan angka murni.
- Urutan tampil: `app_sort_order` lalu `sort_order`.
- Flash publik = window `store_settings.flash_sale_*` + kolom `flash_price` di sini.

### app_forms  (INI yang dipakai kode)
`app_name` PK, `form_fields` (nullable TEXT). Sumber field checkout reseller dan publik.
Route admin `/forms` dan fungsi `getAppFormFields()` membaca/menulis tabel ini.

### testimonials  (INI yang dipakai kode)
`id`, `nama` (nullable), `komentar` (nullable), `balasan_admin`, `created_at` (DATETIME).
Route `/api/testimoni` (GET/POST) dan admin `/testimoni/` memakai tabel ini.

### app_metadata
`app_name` PK, `logo_path` (DEFAULT ''), `app_type` (DEFAULT 'lainnya'), `created_at`.
- `logo_path` adalah slug R2 (`logos/<slug>`), bukan URL. Validasi slug: `^[a-z0-9-]{1,64}$`.
- `app_type` enum: streaming, music, editing, study, game, lainnya.

### store_settings  (SINGLETON)
`id INTEGER PRIMARY KEY CHECK (id = 1)` -> selalu satu baris, id=1.
Selalu `UPDATE ... WHERE id=1`; jangan INSERT baris baru.
- Kontrol toko: `is_closed` (0/1), `auto_schedule` (0/1), `open_time` (DEFAULT '05:00'),
  `close_time` (DEFAULT '22:00'), `close_message`.
- Flash publik: `flash_sale_start`, `flash_sale_end`, `flash_sale_name`, `flash_sale_description`.
- Flash reseller: `flash_reseller_start`, `flash_reseller_end`, `flash_reseller_name`,
  `flash_reseller_description`.
- Mismatch default yang perlu diingat: schema `close_time` DEFAULT '22:00', tapi fallback
  kode admin memakai '23:00' saat kolom kosong. Kalau baris settings belum pernah di-PUT,
  nilai riil mengikuti DEFAULT schema. Pastikan konsisten saat buat migration awal.
- Window flash dibandingkan sebagai string `YYYY-MM-DD HH:MM` (slice 16) terhadap `nowStr()`.

## 4. Tabel reseller (rsl_)

### rsl_resellers
`id`, `username` (UNIQUE), `pass_hash`, `pass_salt`, `pass_iter` (DEFAULT 150000),
`display_name` (DEFAULT ''), `status` (DEFAULT 'active'), `failed_attempts` (0),
`locked_until`, `last_login_at`, `created_at`, `whatsapp` (DEFAULT ''), `x_username` (DEFAULT '').
- `status` enum: active, pending, suspended. Register insert 'pending'; admin approve -> active.
- `pass_iter` = iterasi PBKDF2. JANGAN ubah nilai existing, atau hash lama jadi tidak
  terverifikasi. Password baru memakai iterasi saat itu; verifikasi memakai `pass_iter`
  yang tersimpan per baris.

### rsl_sessions
`id`, `reseller_id`, `token_hash` (UNIQUE), `created_at`, `expires_at`, `last_used_at`,
`ip`, `ua`, `revoked_at`. Sesi reseller; cookie + header `x-reseller-token`.

### rsl_pricelist
Katalog wholesale. `id`, `app_name`, `category`, `duration`, `price` (TEXT),
`status` (DEFAULT 'Ready'), `notes` (DEFAULT ''), `sort_order` (9999),
`app_sort_order` (9999), `created_at`, `flash_price` (TEXT DEFAULT ''), `flash_sort_order` (9999).
- `status` dinormalisasi admin: hanya 'Sold' atau 'Ready' (kapital).
- Flash reseller = window `store_settings.flash_reseller_*` + kolom `flash_price` di sini.
  Checkout server memakai `flash_price` saat window aktif (authoritative di server).

### rsl_stock_items
`id`, `variant_id`, `fields` (TEXT NOT NULL = CIPHERTEXT JSON), `status` (DEFAULT 'available'),
`order_item_id` (nullable), `created_at`, `sold_at`, `buyer_note` (DEFAULT ''),
`reserved_at`, `reservation_expires_at`.
- `status` enum: available, reserved, sold, disabled.
- `fields` dienkripsi `encryptJSON`; baca via `decryptJSON`/`safeDecrypt`. Query mentah
  tidak akan menghasilkan plaintext yang berguna.
- Relasi ke varian manual (tidak ada FK). `deleteVariant()` menghapus stok child manual.
- Reservasi ('reserved') punya TTL via `reservation_expires_at`; `expireReservations()`
  melepas yang kedaluwarsa (pakai indeks `(status,reservation_expires_at)`).

### rsl_orders
`id`, `reseller_id`, `status` (DEFAULT 'pending_payment'), `total_amount` (INTEGER, rupiah penuh),
`provider` (DEFAULT 'manual'), `provider_ref` (TEXT, nullable), `idempotency_key` (NOT NULL UNIQUE global),
`created_at`, `paid_at`, `delivered_at`, `cancelled_at`, `notes`, `order_code` (DEFAULT '').
- `status` enum: pending_payment, delivered, needs_attention, cancelled, refunded.
- `total_amount` = rupiah penuh (hasil `parsePrice`), BUKAN format "K".
- `provider_ref` diisi provider (manual -> `MANUAL-<id>`). Webhook mencari order via kolom ini.
  Gap indeks: tidak ada indeks di `provider_ref` (lihat "Indeks"). Lookup webhook = full scan.
- `idempotency_key` UNIQUE GLOBAL. Route checkout sudah mengamankannya dengan menyimpan
  `session.id + ':' + key_dari_client`. JANGAN buang prefix `session.id` saat refactor -
  tanpanya, dua reseller dengan payload identik (paket tanpa form + qty sama -> hash djb2 sama)
  akan bertabrakan UNIQUE dan salah satu checkout gagal 500.
- `order_code` punya UNIQUE partial index `WHERE order_code <> ''`. Baris dengan '' boleh banyak;
  begitu diisi harus unik. `generateOrderCode()` retry 10x lalu throw.

### rsl_order_items
`id`, `order_id`, `variant_id`, `app_name`, `category`, `duration`, `qty`,
`unit_price` (INTEGER), `line_total` (INTEGER), `fulfilled_qty` (DEFAULT 0), `form_data` (TEXT DEFAULT '').
- `form_data` = JSON array hasil `cleanFormData` (plaintext field yang diketik reseller,
  bukan kredensial).
- `unit_price` / `line_total` rupiah penuh. `fulfilled_qty` dilacak saat alokasi stok.

### rsl_order_revisions
`id`, `order_item_id` (FK -> `rsl_order_items(id)` ON DELETE CASCADE),
`fields` (TEXT NOT NULL DEFAULT '{}' = CIPHERTEXT), `note` (DEFAULT ''),
`created_by` (DEFAULT 'admin'), `created_at`.
- Satu-satunya tabel dengan FK constraint nyata. Revisi admin atas kredensial item.

### rsl_payments
`id`, `order_id`, `provider`, `provider_tx_id`, `status` (DEFAULT 'pending'),
`gross_amount` (INTEGER), `raw_status`, `created_at`.
- `status` yang ditulis kode: pending (created), settle, refund, dan nilai gagal dari
  webhook (deny/expire/cancel via `markPaymentFailed`).
- `gross_amount` rupiah penuh. Saat ini webhook mencatat `order.total_amount` (tagihan),
  BUKAN nominal yang benar-benar dibayar - baru relevan setelah gateway nyata.

### rsl_cred_templates
`id`, `app_name` (UNIQUE), `fields` (TEXT NOT NULL DEFAULT '[]'), `updated_at`.
- `fields` = JSON array nama field (plaintext, hanya schema form, bukan nilai).
  Dipakai untuk pre-fill builder stok admin.

### rsl_reg_tokens
`id`, `token_hash` (UNIQUE via index terpisah `idx_rsl_reg_tokens_hash_unique`),
`token_prefix`, `label` (DEFAULT ''), `duration_hours`, `created_at`, `expires_at`,
`consumed_at` (nullable).
- Token pendaftaran reseller. Konsumsi atomik via
  `UPDATE ... WHERE consumed_at IS NULL AND expires_at>?`.
  Cek `meta.changes===1` untuk pastikan satu pemakaian.

### rsl_ip_throttle
`ip` PK, `login_fails`, `login_window_start`, `login_locked_until`, `updated_at`.
- Throttle login reseller per IP (lapis pertama; WAF rate-limit adalah lapis kedua).

### rsl_audit
`id`, `actor_type`, `actor_id` (nullable), `action`, `entity_type`, `entity_id` (nullable),
`meta` (TEXT = JSON string), `ip`, `created_at`.
- `actor_type`: guest, reseller, admin, system. `meta` di-JSON.stringify saat tulis.

## 6. Tabel hantu (legacy, JANGAN dipakai)

Ada pasangan tabel kembar dari versi lama. Kode produksi TIDAK menyentuh yang kiri.
Jangan tulis query ke sana; kalau ragu, cek route mana yang membaca tabel mana.

| Hantu (jangan pakai) | Yang aktif (pakai ini) | Pembeda |
|---|---|---|
| forms | app_forms | forms.form_fields NOT NULL; kode baca/tulis app_forms |
| testimoni (tunggal) | testimonials (jamak) | testimoni.nama/komentar NOT NULL; route pakai testimonials |

Kalau nanti mau bersih-bersih, arsipkan/drop yang hantu setelah yakin tidak ada reader lama.
Sampai saat itu, anggap mereka read-only artefak.

## 7. Uang - dua format, jangan tertukar

| Format | Contoh nilai | Kolom | Parser |
|---|---|---|---|
| TEXT manusia | 50K, 100.000, 1.2jt | pricelist.price/flash_price, rsl_pricelist.price/flash_price | parsePrice (backend), resNum/extractNumK (frontend) |
| INTEGER rupiah penuh | 50000, 100000 | rsl_orders.total_amount, rsl_order_items.unit_price/line_total, rsl_payments.gross_amount | hasil parse, disimpan sebagai angka |

Aturan:
- Kolom TEXT katalog = apa yang ditampilkan dan diedit admin.
- Kolom INTEGER order/payment = hasil konversi saat checkout, dipakai untuk total dan pencatatan.
- Konversi K -> x1000 harus konsisten di ketiga parser (`parsePrice`, `resNum`, `extractNumK`).
  Kalau salah satu berubah, harga flash/checkout bisa tidak sinkron antara tampil dan ditagih.
- Server selalu menghitung ulang `unit_price` dari katalog saat checkout (authoritative).
  Frontend hanya menampilkan. Jangan pernah kirim harga dari client untuk dipercaya server.

## 8. Enum status (nilai valid)

| Tabel | Kolom | Nilai |
|---|---|---|
| rsl_orders | status | pending_payment, delivered, needs_attention, cancelled, refunded |
| rsl_stock_items | status | available, reserved, sold, disabled |
| rsl_resellers | status | active, pending, suspended |
| rsl_payments | status | pending, settle, refund, deny, expire, cancel |
| pricelist / rsl_pricelist | status | Ready, Sold (kapital) |
| app_metadata | app_type | streaming, music, editing, study, game, lainnya |

State machine order (dari fulfillment), ditulis ASCII:
- pending_payment -> (settle) -> delivered
- pending_payment -> (stok kurang saat alokasi) -> needs_attention
- pending_payment -> (fail/expire) -> cancelled
- delivered -> (refund) -> refunded
- needs_attention -> (retry fulfill) -> delivered
- needs_attention -> (refund) -> refunded

Transisi dijaga `WHERE status IN (...)` di UPDATE. Andalkan guard itu, jangan update buta.

## 9. Indeks: yang ada dan gap

Indeks yang sudah ada (cukup untuk query panas saat ini):
- rsl_stock_items: (variant_id,status), (order_item_id), (status,reservation_expires_at).
  Mendukung reserveStock, releaseOrderReservations, expireReservations.
- rsl_orders: (reseller_id), (status), (reseller_id,idempotency_key), unique partial order_code.
- rsl_order_items: (order_id), (variant_id).
- rsl_payments: (order_id).
- rsl_audit: (actor_type,actor_id), (created_at).
- rsl_pricelist: (app_name), (app_sort_order,sort_order,id).
- rsl_reg_tokens: (expires_at), (consumed_at), unique (token_hash).
- rsl_sessions: (expires_at), (reseller_id).
- rsl_order_revisions: (order_item_id).

Gap yang perlu diperhatikan:
- rsl_orders.provider_ref TIDAK punya indeks. Webhook dan manual.createPayment lookup via
  kolom ini -> full scan. Volume kecil aman, tapi begitu gateway nyata aktif (webhook sering),
  tambahkan: `CREATE INDEX idx_rsl_orders_provider_ref ON rsl_orders(provider_ref);`
- Tidak ada indeks di rsl_orders.provider (tidak dibutuhkan saat ini).
- pricelist tidak punya indeks (app_sort_order,sort_order) seperti rsl_pricelist; katalog
  publik kecil sehingga SELECT * tanpa ORDER terindeks masih oke, tapi kalau membesar,
  pertimbangkan.

## 10. Query cheat-sheet (yang benar)

Katalog reseller dengan stok tersedia (pola listCatalog):

```sql
SELECT
  p.id, p.app_name, p.category, p.duration, p.price, p.status, p.notes,
  p.sort_order, p.app_sort_order, p.flash_price, p.flash_sort_order,
  (SELECT COUNT(*) FROM rsl_stock_items s
   WHERE s.variant_id = p.id AND s.status = 'available') AS stock_available,
  f.form_fields
FROM rsl_pricelist p
LEFT JOIN app_forms f ON p.app_name = f.app_name
ORDER BY COALESCE(p.app_sort_order, 9999), COALESCE(p.sort_order, 9999), p.id;
```

Cek idempotency per reseller (pola checkout - NOTE prefix session.id disimpan di kolom):

```sql
SELECT id FROM rsl_orders WHERE idempotency_key = ? AND reseller_id = ?;
```

Lepas reservasi kedaluwarsa (pola expireReservations, pakai indeks composite):

```sql
UPDATE rsl_stock_items
SET status = 'available', order_item_id = NULL, reserved_at = NULL,
    reservation_expires_at = NULL
WHERE status = 'reserved' AND reservation_expires_at <= ?;
```

Ambil stok available untuk varian (pola reserveStock, subquery ORDER BY id LIMIT):

```sql
UPDATE rsl_stock_items
SET status = 'reserved', order_item_id = ?, reserved_at = ?, reservation_expires_at = ?
WHERE id IN (
  SELECT id FROM rsl_stock_items
  WHERE variant_id = ? AND status = 'available'
  ORDER BY id LIMIT ?
);
```

Baca settings singleton (selalu id=1):

```sql
SELECT * FROM store_settings WHERE id = 1;
```

Konsumsi token registrasi atomik (cek meta.changes===1):

```sql
UPDATE rsl_reg_tokens SET consumed_at = ?
WHERE token_hash = ? AND consumed_at IS NULL AND expires_at > ?;
```

## 11. Checklist sebelum tulis query / migration baru

1. Cocokkan nama kolom dengan schema live (sqlite_master), jangan dari memori.
2. Uang: pastikan menulis ke kolom INTEGER (rupiah penuh) atau TEXT (format manusia) yang benar.
3. Waktu: simpan UTC via nowStr()/datetime('now'); jangan campur zona.
4. Enkripsi: rsl_stock_items.fields dan rsl_order_revisions.fields = ciphertext; selalu lewat
   encryptJSON/decryptJSON. Jangan pernah tulis plaintext ke kolom ini.
5. Singleton: store_settings hanya id=1; pakai UPDATE, bukan INSERT.
6. Idempotency: jangan buang prefix session.id pada idempotency_key; UNIQUE-nya global.
7. FK: hanya rsl_order_revisions yang cascade. Tabel lain -> hapus child manual sebelum parent.
8. Status: hormati enum dan guard WHERE status IN (...); jangan update status buta.
9. Tabel hantu: pastikan tidak tidak sengaja menulis ke forms atau testimoni.
10. Indeks baru: kalau tambah query panas by kolom yang belum terindeks (mis. provider_ref
    saat gateway aktif), buat indeksnya di migration yang sama.
11. Migration: D1 tidak punya transaction multi-statement atomik seperti RDBMS penuh;
    batch() best-effort. Untuk perubahan schema+data kritis, pisahkan langkah dan verifikasi.
12. Setelah ubah schema, perbarui file catatan ini dan version-query aset frontend terkait.

## 12. Relasi logis (tanpa FK, dijaga aplikasi)

Ditulis ASCII, format `parent -> child (kolom fk)`:

```
rsl_resellers -> rsl_sessions (reseller_id)
rsl_resellers -> rsl_orders (reseller_id)
rsl_orders -> rsl_order_items (order_id)
rsl_orders -> rsl_payments (order_id)
rsl_pricelist -> rsl_stock_items (variant_id)
rsl_order_items -> rsl_stock_items (order_item_id, saat reserved/sold)
rsl_order_items -> rsl_order_revisions (order_item_id, FK CASCADE)
app_forms / app_metadata -> pricelist / rsl_pricelist (app_name, longgar)
```

Semua relasi di atas (kecuali revisions) tidak punya constraint DB. Integritas dijaga oleh
kode di db.js / fulfillment.js. Kalau tambah tabel/relasi baru, catat di sini dan pastikan
kode pembersihnya (delete/release) ikut ditulis, karena DB tidak akan menolong mengcascade.
